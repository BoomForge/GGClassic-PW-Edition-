# Texture streaming and bounded memory management

## M1 — resource ownership audit and live diagnostics (26 November 2026)

Source implementation through 53f794f7. M1 full Windows compilation and all 11 workflows passed at 1a3a5316. Actual measured Windows baseline remains outstanding.

### Actual architecture
- Shared/Image/CImageC.cpp owns a process-wide m_List (image ID to tagImgData). Mesh and UI callers can retrieve the raw resource and shader-resource-view pointers; removing an image ID alone cannot be assumed safe for every material or render binding.
- Common-Images.cpp has separate high-level filename banks for images and textures. Some lookups are case-sensitive, one is case-insensitive, and the DDS/PNG fallback can resolve distinct requested strings to one physical file. Existing cache keys also do not consistently distinguish loader mode, quality and texture divide. Do not globally collapse image IDs until usage/compatibility is understood.
- The image SDK's FindInternalImage scans names across the registry; LoadImageCoreInternal also consults the high-level texture bank. Embedded DBO texture callers can therefore share entries. Character Creator has a deliberate ID exclusion.
- DDS fast path creates the full supplied mip chain using DirectX::CreateDDSTextureFromFile. Reduced-quality path currently decodes, sometimes decompresses, resizes and recompresses before upload; PNG and unusual DDS paths have separate fallback behavior. This is load-time size reduction, not streaming.
- An existing preload worker uses g_image_list and g_image_outputv and builds GPU textures via PreloadThreadSafeImage. It is batch-prefetch, not a budgeted residency scheduler; audit transfer/cancellation and COM ownership before reuse. In particular, compare the pointer transfer across image_preload_files_finish, image_thread_function and image_preload_files_reset.
- RemoveImage releases lpTextureView in DX11 whereas ImageDestructorD3D releases both lpTextureView and lpTexture. Audit actual AddRef/Release paths, mesh/shader consumers and transferred preload resources before making any ownership change. A leak is plausible but not proven by source asymmetry alone.
- game_freelevel tears down entities, physics, weapons, grass, projectiles and other resources. Standalone then deletes entities and lightmaps, clears lightmap textures, and conditionally clears entitybank textures when standalonefreememorybetweenlevels is enabled. Editor Test Level intentionally retains editor assets; its cleanup cannot simply purge the registry.

### Enable and collect
In PW Edition menu choose **Capture Texture Memory (CSV)**, then load a test map and enter/exit Test Level. Standalone: set GGCPW_PROFILE_TEXTURES=1 in the environment before launch. Capture off by default. Output: %TEMP%\\GGCPW-texturetrace-<pid>.csv. Capture includes immediate editor toggle, level_init_begin, level_ready, gameplay (at most once per five seconds), level_cleanup_begin and level_cleanup_end. The existing load diagnostics CSV can be captured alongside it for timing.

- Estimated registered texture bytes: actual DX11 resource dimensions, mip levels, format slice pitch (DirectXTex ComputePitch), array faces, volume depth, samples, deduplicated by resource pointer. Separately counts staging bytes and aliases. Unknown entries are counted, not fabricated. This is logical allocation size, not exact physical VRAM, driver padding, or live residency. Observed peak is sampled, not an allocation-time high-water mark.
- DXGI adapter3 node zero local/non-local process usage and budget are measured on the actual renderer adapter when available, with validity flags. Local memory may be shared on UMA systems. It includes resources outside the registry.
- Windows working set, private committed bytes, peak working set; process-valid flag. Does not include per-category CPU staging or unregistered preload allocations as texture estimates.
- The diagnostic samples the registry on the game thread, never calls the cached-access getters, never deletes or rebinds resources. It does not scan the worker's mutable queue. No budget enforcement, unloading or streaming is claimed.

### Benchmark and acceptance
Use same Windows GPU, resolution, quality and identical assets. Capture empty map, small populated map, texture-heavy map, three consecutive Test Level runs, two standalone level transitions, five minutes of steady movement. Compare level_ready, cleanup_end, steady samples, sampled peak, actual DXGI usage/budget and process private bytes. Retained editor assets are not automatically leaks; compare deltas across repeated identical runs. Record unavailable DXGI telemetry separately. Test mixed DDS/PNG, sky/cube, terrain, grass, lightmaps, HUD, asset preview, weapons, Character Creator and exported games. Attach traces and frame-time/load timing. No baseline numbers invented.

## M2 — targeted resource and cache repairs (26 November 2026)

Source through e0b37c1f. M1 head 1a3a5316 passed all 11 workflows including [full Windows x64 #45786608087](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45786608087); third-person lifecycle M2 head 8d85af96 also passed all 11, including [full Windows x64 #45785840668](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45785840668).

### Confirmed source defects and repairs
- Old preload finish reused only same-index filenames and copied pointers; worker cleared the old output vector without releasing unmatched references. Cancellation could discard transferred references, and load paths that detached a preload but did not consume it could leak it. Now each non-null entry owns one reference, moves null the source, unmatched and cancelled entries release, unused detached resources release, reset joins before clearing, and image teardown resets the worker.
- Old renderer inspected the mutable completed vector while the worker was pushing into it, and cancellation/active flags were non-atomic. New completed-output mutex, atomic flags, move-transfer ownership, join-before-reset. Renderer checks available completed entries without joining an unfinished batch; existing ordinary loader remains fallback. Worker creation failure releases pending references. Existing GG_GetRealPath/legacy D3DX decoder thread-safety still requires runtime scrutiny; no claim all other registry consumers are thread-safe.
- Old preload matching compared only filename suffixes or same-index names, ignored mip policy and could reuse a full allocation for reduced-quality requests. New bounded full Windows path normalization, case-insensitive exact match and mip policy; descriptor checks for dimensions, 2D resource, array size, sample count and format. Reduced-size, cube/volume, incompatible or converted textures fall back. Non-DDS reuse limited to matching BGRA. Metadata read failures return before using uninitialised metadata.
- Old bank lookups could return a reserved but missing image ID as loaded. SDK internal loader now checks ImageExist before returning a bank hit. High-level image/texture loaders restore a missing resource at its original ID and return zero on failure. Existing case/filename, DDS fallback and ID policy otherwise unchanged; no global alias consolidation or live resource rebinding.
- No changes to global RemoveImage lpTexture ownership because raw view/resource consumers and CreateReplaceImage borrowed/external ownership need explicit audit. No unsafe blanket extra Release, no in-game eviction, no material/grass/terrain changes. Actual RAM/VRAM reduction and frame times require M1 CSV traces and repeat Windows benchmarks.

Regression source guards added for ownership transfer, releases, matching, stale-ID recovery, and shutdown. Full M2 compile and licensed runtime tests pending. Test reordered batches, cancellation while worker loads, missing/corrupt files, same basename in different folders, mip-1 vs all mips, texture quality changes, mixed formats, sky/grass, repeated Test Level and standby/quit. Next M3: configurable advisory memory budgets and deterministic residency planner (pinned resources, generation/ref ownership) without evicting borrowed raw pointers; M2 follow-up audit of actual consumer bindings remains required before M4 real swaps/eviction.

## M3 — advisory texture memory budgeting (26 November 2026)

M2 head 81d97ffe passed ten workflows but [full x64 run #45789815735](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45789815735) failed C2338 at PWPreloadPath. Fixed by using the actual destination array capacity for GetFullPathNameA, rejecting truncated paths. Full build requires revalidation.

M3 adds PW-TextureBudget.h, a deterministic side-effect-free policy. Opt in with GGCPW_TEXTURE_BUDGET=1 (or the existing Capture Texture Memory CSV toggle); GGCPW_TEXTURE_BUDGET_MB accepts decimal MiB, 0/absent for automatic, invalid input falls back to auto and is logged. Automatic logical target is 70% of current DXGI local budget or dedicated adapter capacity if telemetry is unavailable. Manual targets are capped by known automatic headroom; no capacity and no override means unknown target. DXGI process pressure separately flags usage above 90% of its budget. Percentages are initial heuristics, not measured optimal defaults. Existing M1 CSV schema unchanged; separate %TEMP%\\GGCPW-texturebudget-<pid>.csv reports registered GPU estimate excluding staging, target, excess, DXGI pressure, pinned render/special/legacy bytes and unknown entries.

All current registry resources remain pinned, including ordinary legacy textures whose raw bindings may be borrowed. Future planner orders explicitly unpinned, exclusively owned, reloadable, generation-tagged candidates by priority, oldest use then ID; rejects duplicate IDs and unknown generations. No live candidates admitted and no actual evictions. Isolated C++ tests added to existing load profiler smoke executable. CI and licensed runtime benchmarks pending. M4 requires safe binding/ownership, generation-safe decode/upload and fallback; M5 actual residency. No merge/release, measured VRAM saving or hard memory cap claimed.

## M4A — bounded background DDS preparation and render-thread upload (26 November 2026)

M3 head fead99c6 passed all 11 workflows, including [full Windows x64 #45790876015](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45790876015) and [policy tests #45790876235](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45790876235). This also verifies the M2 compile correction.

New opt-in GGCPW_TEXTURE_STAGE=1. On each level, remember up to 128 unique resolved paths from the ordinary full-quality multi-mip DDS fast loader. The next level init starts a separate CPU-only worker on those in-process hints; the first visit has no prior hints, and a different level may miss. No disk manifest, path guessing, encrypted image block staging, PNG conversion or legacy GPU worker change. Worker reads file in 256 KiB chunks, validates identity/size/write time and DDS metadata, rejects cubes/arrays/volumes/typeless/single-mip data. Bounded initial policy: 16 MiB per file and 64 MiB charged per batch including consumed/in-flight files. Cancellation stops between chunks/files; synchronous OS read or join can still block on slow storage. No worker graphics or GG_GetRealPath calls.

Ordinary load thread checks ready results by resolved path and generation, takes ownership without waiting for unfinished work, checks metadata and reopens same file for identity check with no concurrent writes during upload. Native CreateDDSTextureFromMemory uses original DDS mip data and validates resulting descriptor before normal image registration. Miss/invalid/failed upload uses existing file loader. No material rebinding or image ID changes; no live replacement. Level cleanup and image teardown cancel, join and clear staged payloads. %TEMP%\\GGCPW-texturestage-<pid>.csv logs per-generation prepared files/bytes, successful uploads, misses, invalid and next hints. Initial C++ smoke tests cover file bounds, cancellation, signature and same-file validation. Full current CI/runtime unverified.

M4 remains partial: no actual low-mip-first or progressive swaps, no per-frame upload scheduler, no visibility-based residency. The resource audit confirms raw view pointers remain borrowed; M4B must implement explicit ownership/binding and generation-safe replacement or equivalent stable indirection before mip promotion. Current work accelerates eligible repeated loads, not measured yet; all registered GPU textures remain pinned. Benchmark opt-in vs off for repeated same-level test/standalone transitions, changed files, cancel, malformed/missing DDS, PNG, sky, terrain, grass and materials; compare stage counters and M1/M3 CSVs, RAM, load times, frame times. No release/master merge.

## M4B — stable-resource progressive mip promotion (26 November 2026)

M4A head e4502124 passed all 11 workflows, including [full Windows x64 #45792732215](https://github.com/BoomForge/GGClassic-PW-Edition-/actions/runs/45792732215). M4B source adds PW-TextureMip.h and integration with the staged DDS path. Opt-in both GGCPW_TEXTURE_STAGE=1 and GGCPW_TEXTURE_PROMOTE=1; only explicitly marked ordinary entitybank/user textures ending _pwstream_d.dds, full quality, ordinary texture mode, full authored mip chain, BC1/BC3 (including sRGB), <=2048 dimensions, eligible ready cache hit. All other files stay on existing full-load route. Explicit marker is a test restriction, not automatic material discovery. First visit records hints; next load can use staged data if ready. Legacy GPU preload hits may bypass it. No UI/terrain/grass/sky/lightmap/render-target/cubemap/PNG changes intended.

Audit: GetImagePointer and GetImagePointerView return borrowed raw resource/view pointers; CreateReplaceImage overwrites them without a registry of external bindings. Rather than swapping pointers, create a D3D11 default shader-resource texture with RESOURCE_CLAMP, upload original mip tail (<=256), set resource minimum LOD; on immediate context lower clamp and upload one authored mip before the next draw. Stable resource and SRV identity and original image dimensions/ID; queue owns independent COM reference and decoded CPU bytes, carries level generation. Up to 8 pending, one subresource per game_main_loop (<=4 MiB); this is an upload byte limit, not a guaranteed frame-time limit. Worker decodes marked DDS only with reserved <=6 MiB, raw+decoded charged against same 64 MiB batch. Complete pending resource on raw GetImagePointer access; level cleanup drains rather than leaving retained editor assets partially resident, then releases queue refs. Device removal drops pending work; full existing device-reset acceptance still needed. No use of global RemoveImage ownership change. Metadata/creation/miss/unsupported cases use full-load fallback. M4B does not yet capture every direct readback or arbitrary custom shader Load access; marked textures must use ordinary sampled diffuse materials. No guaranteed savings: resource clamp may reduce physical residency but full logical allocation remains; measure DXGI and gameplay. No M5 eviction/demotion/visibility yet.

Stage CSV adds mip_started/steps/finished (new process recommended for new schema). Isolated Windows WARP test creates synthetic BC1, checks tail clamp and promotion, stable SRV resource identity and mip0 readback, plus policy limits. Current CI and real licensed rendering remain pending. Test marked asset on repeat level, verify visual transitions, no black/flicker, CPU readback, repeated Test Level, export and actual GPU memory/frame times, with disabled fallback. Next M5 measured residency, visibility and priority/demotion policy after M4B validation; do not treat as proven VRAM savings. No release/master merge.
